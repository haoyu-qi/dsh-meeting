# DeepSeek Harness Meeting Plugin V0.1 — 原型设计记录

> 配套文档：[interaction-v0.1.md](interaction-v0.1.md)（交互设计）、[prd-v0.1.md](prd-v0.1.md)（需求）。
>
> 本文记录 V0.1 高保真原型两块画板：**浅色「交互流程概览」**（5 步核心闭环 + 主界面/侧栏/共享视图/结果卡）与**深色「6 屏集成稿」**。逐屏规格以本档为准；原始 PNG 存放于 `docs/mockups/`。

## 0. 设计语言

- **双主题**：流程板为浅色（白卡片 + 蓝色主按钮），集成稿为深色（VS Code 风格深灰底、蓝色主操作、绿色成功态、红色危险/结束态）。→ 插件 UI 必须跟随 DSH 主题 token，**两套主题都要兼容，禁止硬编码色值**。
- **侧栏分区顺序统一**：成员 → 共享状态 → 实时转写 → 当前讨论 / 任务建议 → Agent 状态。
- **状态符号**：🎤 正在发言；🔇（红斜杠）静音；● 协作中；`M` 文件修改标记；`+x -y` diff 计数；`高优先级` 红色标签；`主持人` Host 徽标。

## 1. 画板一：交互流程概览（浅色，核心闭环 5 步）

### 1.1 进入协作
- Harness 顶部导航：`DeepSeek Harness ｜ Project ｜ Agent ｜ Plan ｜ 协作③`（③ = 附近房间数徽标）；
- 面板「附近协作房间」：`登录模块问题讨论 · 浩宇 · 3人 [加入]`、`API联调 · 张伟 · 2人 [加入]`；
- 底部 `＋ 创建协作房间`。

### 1.2 加入会议
- 面板头：`协作中 · 登录模块问题讨论`（可折叠 ▾）；
- 成员（3）：`浩宇 (你) 🎤`、`张伟 🎤`、`李强 🔇`；
- 共享状态区：`张伟正在共享屏幕` + 实时代码缩略图。

### 1.3 共享屏幕 & 语音讨论
- 实时转写区：`16:21 浩宇 为什么这里调用了两次？`、`16:21 张伟 应该是 useEffect 这里。`、`16:22 浩宇 对，依赖没处理好。`；
- 底部控制条：🎤 麦克风、🖥 共享、**红色挂断**（结束协作）。

### 1.4 Agent 介入
- `Agent ｜ Chat` 双 Tab；
- 用户消息气泡：`看看刚才讨论的问题。`；
- Agent：`正在分析 Login.tsx…` + 进度清单 `✓ 读取文件`、`✓ 分析依赖关系`、`○ 生成结论`。

### 1.5 Agent 执行任务
- 用户：`就按这个方案改掉。`；
- Agent：`任务执行中…` + `✓ 修改 Login.tsx`、`✓ 修改 auth.ts`、`○ 运行测试`。

### 1.6 协作中主界面（集成在 Harness 内）
三栏 IDE 布局：
- 顶栏：`DeepSeek Harness ｜ Project A ｜ Agent ｜ Plan ｜ 协作3`；
- 左：EXPLORER（Project A：src/components、pages/Login.tsx、api、utils、types、App.tsx、index.tsx、styles.css、package.json、tsconfig.json）；
- 中：编辑器 Login.tsx（`useState(false)` 的 loading、`useEffect` 内两次 `fetchData()`、依赖 `[token]`）；
- 右：Agent 面板——用户 `为什么这里接口会调用两次?`；Agent：`正在分析 Login.tsx…` → 结论 `1. useEffect 依赖 [token] 变化导致重复执行 2. React.StrictMode 触发两次 effect`；建议 `检查 token 是否在短时间内变化 或使用 useRef 控制只执行一次`；收尾 `是否需要我帮你修改?`；底部输入框。

## 2. 画板二：6 屏集成稿（深色）

1. **协作入口与附近房间**：完整应用框（顶栏 + Explorer 树）；协作面板含 3 个房间条目（登录模块问题讨论/浩宇·3人、API联调/张伟·2人、新功能方案讨论/李强·4人）+ 大按钮 `＋ 创建协作房间`；
2. **创建协作房间**（模态）：名称输入（默认 `Project A 协作讨论`）、当前项目下拉（Project A）、`☑ 允许 Agent 获取会议上下文`、`☑ 允许共享当前项目上下文`、`[取消] [开始协作]`；
3. **协作中主界面**：`← Project A 协作讨论 ｜ ● 协作中·3人`；Agent 面板含代码块引用（45–48 行 `useEffect` 双调用）；侧栏：成员 / 共享状态（`张伟正在共享屏幕 · VS Code · Login.tsx · [查看共享]`）/ 实时转写（带 `● 录制中` 指示 + `查看全部 >`）；底部操作条：`🎤 静音 ｜ 🖥 共享屏幕 ｜ ⏺ 转写 ｜ 👥 成员 ｜ [退出协作]`；
4. **屏幕共享视图**：`张伟的共享屏幕 [退出查看]` 全幅视图 + 底部 `Agent: 已同步当前共享内容`；
5. **Agent 介入与任务建议**：`当前讨论: 登录接口重复请求 · AI识别: 可能涉及 Login.tsx`；`任务建议: 优化登录接口，避免重复请求 [高优先级]`；按钮 `[让 Agent 实现] [记录为决策]`；`Agent 状态: 正在分析 Login.tsx`；
6. **Agent 执行结果与同步**：Explorer 中 `Login.tsx` 出现 `M` 标记；Agent 面板：`✓ 任务已完成（绿） 优化登录接口，避免重复请求`；`修改的文件 (2)：src/pages/Login.tsx +18 -6；src/api/auth.ts +12 -2`；`测试结果: ✓ npm test 通过 · 所有测试用例已通过`；侧栏同步：成员（`张伟 (主持人)`）、`Agent 状态: ✓ Agent 已完成任务 · 2 个文件已修改 · ✓ 测试通过 · [查看结果]`、转写 `16:30 李强 Nice!`。

## 3. 原型相对交互稿的新增细节（需回填需求）

| # | 新增细节 | 建议 |
|---|---|---|
| 1 | 成员 `主持人` 徽标（Host 标识在 UI 可见） | 纳入成员模型：`member.role = host \| member`，V0.1 |
| 2 | 任务建议卡带 `[高优先级]` 标签、`[记录为决策]` 按钮 | 纳入 §11.5/§11.6 卡片规格 |
| 3 | 文件级 diff 计数（`+18 -6`）与 Explorer `M` 标记 | 结果卡规格细化 |
| 4 | 底部操作条组成：静音 / 共享屏幕 / 转写 / 成员 / 退出协作 | 侧栏规格定稿 |
| 5 | 转写区 `● 录制中` 状态指示 | 转写 UI 规格（仅指示，非云端录制） |
| 6 | 共享视图保留应用级导航头（`← Project A 协作讨论`） | 协作视图在 Harness 中心区以"页面"形式存在，非全屏遮罩 |
