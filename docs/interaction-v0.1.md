# DeepSeek Harness Meeting Plugin V0.1 — 交互设计

> 配套文档：[prd-v0.1.md](prd-v0.1.md)（PRD 定义做什么，本文定义怎么交互）。
>
> 核心立场：交互重点**不像传统会议软件**围绕"入会、摄像头、成员宫格"，而是围绕：
>
> **进入协作 → 看同一个问题 → Agent 理解上下文 → Agent 接手执行**
>
> 首版整体交互 = **一条核心闭环 + 两个辅助入口**。

---

## 1. 设计总原则

1. **不做一级"大会议模块"**：只增加一个「协作」入口；
2. **只有 3 个核心界面**：协作大厅（附近房间 + 创建房间）、协作侧边栏（成员 / 语音 / 共享状态 / 最近转写 / Agent 状态）、共享屏幕视图；
3. **其余全部复用 Harness**：Agent Chat、Plan、Diff、Terminal、File、Git 一概不重做；
4. **视觉优先级：共享内容 > Agent > 参会人**；绝对不做 Zoom 式九宫格；
5. **用户不离开 Harness，不复制会议内容到 Agent 对话框**。

## 2. 整体交互主线

```
打开 DeepSeek Harness
        ↓
进入当前 Project / Workspace
        ↓
点击「协作」→ 附近协作房间 / 创建
        ↓
进入协作房间：语音讨论 + 屏幕共享
        ↓
Meeting Plugin 持续获取「谁在说 + 说了什么 + 正在看什么」
        ↓
形成 Meeting Context
        ↓
用户："Agent，你看一下刚才的问题"
        ↓
Agent 自动结合 会议上下文 + 当前 Workspace → 分析代码 / 给方案
        ↓
用户："就按这个改"
        ↓
Harness 原生 Agent 执行 → Diff / Test / Result
        ↓
会议继续
```

## 3. 入口与协作大厅

入口形态（二选一，最终以 Harness 原生布局适配为准）：

```text
[Agent] [Plan] [协作 ③]        # 顶部，③ 为附近房间数
```

或右上角 `🤝 协作`。点击展开右侧 Panel。

**未加入会议状态（协作大厅）**：

```text
┌───────────────────────────┐
│ 协作                       │
├───────────────────────────┤
│ 附近协作房间               │
│                           │
│ ● 登录模块问题讨论         │
│   浩宇 · 3人               │
│                   [加入]   │
│                           │
│ ● API联调                  │
│   张伟 · 2人               │
│                   [加入]   │
│                           │
│ ───────────────────────   │
│                           │
│      + 创建协作房间        │
└───────────────────────────┘
```

- 不需要输入：会议号 / 服务器地址 / IP 地址——这是局域网模式最大的体验优势；
- 房间条目：`● 名称 · 发起人 · 人数 · [加入]`。

## 4. 创建协作房间（极简表单）

不弹复杂表单，直接出现：

```text
创建协作

名称
[ Project A 协作讨论        ]

当前项目
Project A

☑ 允许 Agent 获取会议上下文
☑ 允许共享当前项目上下文

              [开始协作]
```

- 房间名默认 `{项目名} · 协作讨论`，用户直接点**开始协作**即可；
- 两个勾选项把 Agent 上下文授权显式化（对应 PRD §13 安全原则）。

## 5. 协作侧边栏（会议主界面）

```text
┌─────────────────────────────────────────────────────┐
│ Project A                         🤝 协作中 · 3人   │
├────────────┬──────────────────────────┬─────────────┤
│            │                          │ 协作         │
│ Workspace  │       Agent Chat         │             │
│            │                          │ 👤 浩宇 🎤  │
│ src/       │ 用户：                   │ 👤 张伟 🎤  │
│ Login.tsx  │ 为什么这里调用了两次？    │ 👤 李强      │
│ api/       │                          │             │
│ ...        │ Agent：                  │ ─────────   │
│            │ 正在分析 Login.tsx...    │ 🖥 张伟正在 │
│            │                          │   共享屏幕   │
│            │                          │             │
│            │                          │ 🔴 实时转写  │
├────────────┴──────────────────────────┴─────────────┤
│ 🎤 静音     🖥 共享屏幕      💬 转写      退出协作 │
└─────────────────────────────────────────────────────┘
```

- 侧边栏宽度 **280～320px**；
- 组成：成员列表（含 🎤 发言状态）、共享状态、最近转写、Agent 状态、「当前讨论」（见 §12）；
- 底部操作条：`🎤 静音 ｜ 🖥 共享屏幕 ｜ 💬 转写 ｜ 退出协作`。

## 6. 屏幕共享交互

点击 `🖥 共享` → 调用浏览器原生共享选择器（VS Code / 标签页 / 应用窗口 / 整屏）。

**共享者视角**：

```text
🖥 你正在共享
VS Code · Login.tsx
[停止共享]
```

**其他成员视角**：

```text
张伟正在共享屏幕
[查看共享]
```

点击**查看共享**后不打开新会议窗口，而是在 Harness **中心区域临时进入「协作视图」**：

```text
┌─────────────────────────────────────────────────┐
│ 张伟的共享屏幕                       [退出查看] │
├─────────────────────────────────────────────────┤
│                                                 │
│                  VS Code                        │
│             src/Login.tsx                       │
│                                                 │
├─────────────────────────────────────────────────┤
│ Agent：已同步当前共享内容                       │
└─────────────────────────────────────────────────┘
```

## 7. 共享屏幕 → Agent 天然联动（第一个 Wow Moment）

不让用户走 `截图 → 上传 → Agent 分析`，而是天然联动：

```
张伟开始共享 VS Code → Meeting Plugin → Agent 状态：🤖 正在查看共享屏幕
```

此时用户直接说"Agent，看一下这里为什么报错"，系统已知：

```
当前会议 / 当前发言人 / 当前共享者 / 当前共享窗口 / 当前 Workspace / 最近几分钟对话
```

Agent 直接响应。**这是产品的第一个 Wow Moment。**

## 8. 语音与转写（克制）

- 转写默认不占大量空间，右侧只显示**最近 2～3 条**：

```text
🔴 正在转写
16:21 浩宇  这个接口现在重复调用。
16:21 张伟  应该是 useEffect 这里。
```

- 点击 `查看全部 >` 才打开完整 Transcript；
- 用户主要是来**一起解决问题**的，不是来阅读会议字幕。

## 9. Agent 介入的三种方式

| 方式 | 触发 | 行为 |
|---|---|---|
| ① Harness 对话（默认） | 用户输入"看看刚才讨论的问题" | Agent 自动携带 Meeting Context |
| ② 语音唤起 | "Agent，帮我们看看这个问题。" | 识别唤起词 → 🤖 Agent 正在分析...；结果仍显示在原生 Agent 对话区，**不新开 Agent Chat** |
| ③ 会议自动建议（克制） | 讨论中形成决策/任务 | 右侧轻提示卡片 |

方式③的卡片形态：

```text
🤖 Agent 识别到决策
验证码接口第一版采用 Mock
[记录] [让 Agent 实现] ×
```

## 10. 「让 Agent 实现」（第二个核心交互）

```text
检测到任务：实现验证码 Mock
[让 Agent 实现]
```

点击后**不在 Meeting Plugin 内执行代码**，而是自动向 Harness Agent 发起任务：

> 根据当前会议上下文，实现刚才确认的验证码 Mock 方案。

随后**完全回归 Harness 原生交互**：

```
Agent 生成 Plan → 读取文件 → 修改代码 → 权限确认 → Terminal → Diff
```

插件因此非常轻。

## 11. Agent 执行状态与结果联动

**执行中**：全体成员在右侧看到可理解的工作状态（不必看到完整 Agent Chain）：

```text
🤖 Agent
● 正在修改 Login.tsx
● 正在运行 npm test
```

状态用人类可读短语：`分析中 / 读取代码 / 修改代码 / 运行测试 / 等待确认 / 已完成`。

**完成后**：Meeting Panel 自动出现结果卡：

```text
🤖 Agent 已完成任务
验证码 Mock 功能
2 个文件已修改 · 测试通过
[查看结果]
```

`[查看结果]` 跳转 Harness 原生 Diff / Agent Result，插件**不重做 Diff 页面**。

## 12. 「当前讨论」Active Context（推荐，V0.1 增加）

右侧常驻一个极短主题，随讨论自动更新：

```text
当前讨论
登录接口重复请求
AI 识别：可能涉及 Login.tsx
        ↓（讨论推进）
当前讨论
验证码 Mock 方案
```

本质是一个超短的 **Active Context**，让所有人和 Agent 随时知道**我们现在在解决什么**——这个体验比单纯转写更有价值。对应 Meeting Context 新增 `topic` 字段（见 PRD §10.1）。

## 13. 会议结束交互

**普通成员退出**：`确定退出当前协作？`

**Host 结束**：

```text
结束协作
结束后其他成员将退出当前房间。
本次协作将保留：
✓ 会议转写  ✓ 技术决策  ✓ Agent任务  ✓ Agent执行记录
[取消]  [结束协作]
```

结束后**不跳"会议记录"**，仍停留在当前 Harness Project；Agent 对话中生成协作总结卡：

```text
协作总结
主题：登录模块问题讨论
决策：• 验证码接口第一版采用 Mock
完成：• Agent 修改 Login.tsx / auth.ts • npm test 通过
待处理：• 对接正式验证码接口
[继续让 Agent 处理]
```

> **会议结束，但开发上下文没有结束。**（总结卡生成为 P1，结束确认交互为 V0.1）

## 14. 核心交互闭环

```
                    DeepSeek Harness
                           │
                    打开 Project A
                           │
                        🤝协作
                           │
             ┌─────────────┴─────────────┐
             │                           │
        创建协作                     加入附近协作
             │                           │
             └─────────────┬─────────────┘
                           ↓
                       协作侧边栏
                           │
               ┌───────────┴───────────┐
               ↓                       ↓
              语音                   屏幕共享
               │                       │
               └───────────┬───────────┘
                           ↓
                    Meeting Context
                           ↓
                     Harness Agent ←── "看看刚才的问题"
                           │
                     Workspace 分析
                           │
                       Agent 执行  ←── "直接改掉"
                           │
                     Diff / Test
                           ↓
                       继续协作
```

## 15. V0.1 三大关键瞬间（交互验收口径）

V0.1 最值得优先设计和验证的不是"怎么开会"，而是三个关键瞬间：

1. **进入 Harness 就能看到附近团队正在讨论什么**；
2. **别人共享代码后，我一句"Agent 看一下这里"，Agent 真能理解**；
3. **讨论完一句"按刚才方案改"，Agent 不需要重复 Prompt 就开始处理**。

> 三个交互成立，产品方向基本就成立。
