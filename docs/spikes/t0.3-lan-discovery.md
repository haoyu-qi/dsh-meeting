- 脚本：`scripts/spikes/lan-discovery.mjs`（Node ESM，双 UDP socket，组播组 `239.255.42.99:51990`）
- 执行日期：2026-08-29 17:46 +08:00
- 执行方式：`node scripts/spikes/lan-discovery.mjs`，一次通过，未重试

## 2. 组播环回结果：PASS（本机环回成功）

发送端 8 秒内成功发出 15 条 announce（0 错误），接收端共收到 27 条，内容与发送 payload 逐字节一致，来源 `198.18.0.1:55894`。原始输出摘录：

两个异常观察（都是生产实现要处理的点，不影响本机 PASS 判定）：

1. **默认组播接口选到了虚拟网卡**：`addMembership(239.255.42.99)` 未指定接口时，系统选择了 Meta TUN（198.18.0.1）作为默认组播接口，而不是真实局域网网卡 `以太网 192.168.31.38`；payload 里 `host` 字段因此也是 `198.18.0.1`。
2. **接收数 > 发送数（27 vs 15）**：怀疑 TUN 适配器对组播包有反射/复制，接收端必须按 announce 内容去重、容忍重复报文。

## 4. 防火墙现状分析

- 三个防火墙配置文件（Domain/Private/Public）**全部启用**，本机没有任何"关防火墙"的侥幸空间。
- 真实局域网 `以太网` 的网络类别是 **Public**（最严格档）。Public 档默认入站策略为"阻断未匹配规则的所有入站"。
- 本机环回组播未受影响，是因为同主机回环流量不经过物理链路，防火墙入站策略基本不拦；**跨主机时 UDP 51990（入站组播）与 TCP 18990（Host 信令）都会被默认阻断**，除非存在针对 node.exe（或打包后应用 exe）的放行规则。
- 推论：产品化必须自带防火墙规则方案（安装器注册 `netsh advfirewall` / NSIS 自定义步骤，或首次运行以管理员提示创建），且规则要覆盖入站 UDP 51990 与 TCP 18990；不能依赖系统弹窗——Public 档下弹窗被无视即永久静默失败。

## 6. 建议 announce 参数

| 参数 | 建议值 | 依据 |
|---|---|---|
| TTL | `setMulticastTTL(1)`（子网范围，不跨路由器） | 房间发现只需同网段；TTL=1 防止组播泄漏到外网/VPN 隧道 |
| multicastLoopback | 保持默认 `true` | 本机 UI 可即时显示自己的房间，本次 spike 即依赖此项 |
| 广播间隔 | spike 500ms；生产建议 **1000ms ± 20% 随机抖动** | 多房间同时 announce 时避免同步风暴；1000ms 足够秒级发现 |
| 房间超时 | 连续 3 个周期（约 3s）未收到即剔除 | 与间隔匹配的离席判定 |
| payload | 单条 JSON ≤ 512 字节（本次 135B），不分包 | 远小于 MTU，避免 IP 分片放大丢包 |
| 接口选择 | **显式**：`addMembership(GROUP, lanIp)` + `sender.setMulticastInterface(lanIp)`，`host` 字段填同一 lanIp | 本次默认接口被 Meta TUN（198.18.0.1）抢占，地址不可路由到真实 LAN；需按"非 internal、非 198.18.0.0/15、非 100.64.0.0/10、有默认网关"挑选真实网卡 |
| socket 选项 | 双 socket 均 `reuseAddr: true`；接收端 bind 51990 | 本次验证 Windows 下可正常共存 |
| 去重 | 接收端按 `(roomId, host, port)` 幂等合并、刷新 TTL | 本次观测到 27 收 > 15 发的重复投递 |

## 7. 遗留风险

1. **企业/家庭 AP 客户端隔离（wireless isolation）**：会在二层直接丢弃站间组播与单播，本机环回完全探测不到，必须两台真机在同一 AP 下互测（发/spike 脚本分别在两台跑即可）。
2. **Windows 防火墙跨主机阻断**：以太网为 Public 档且全配置文件启用，跨主机 UDP 51990 / TCP 18990 入站默认被拦；需验证放行规则创建流程，否则第二台机器复测会误判为组播失败。
3. **虚拟网卡抢占**：Meta TUN（198.18.0.1）与 Tailscale（100.72.122.31）会干扰默认接口选择与 `host` 字段，生产实现必须显式选卡，并对选卡结果做用户可见提示（或允许手动指定）。
4. **组播重复投递**：TUN 反射导致接收数偏多，去重逻辑缺失会表现为房间列表闪烁/计数错误。
5. **网络类别可变**：用户随时可把"网络 4"改回 Private 或换网，代码只能依赖实际端口连通性（或安装器规则），不能依赖 NetworkCategory 判断。
